Three things never to do at the venue:
  • Never pass -Rebuild and never run make rebuild — a rebuild needs the npm and PyPI registries.
  • Never run .\stop.ps1 -Wipe or make clean — those delete the volumes holding ~1.3 GB of cached CLIP/Chroma weights and the ArcFace pack.
  • Stop your other Docker projects first: docker stop $(docker ps -q). Several stacks alongside this one starve the daemon on 16 GB.

Do not demo these. Anything phrased as a negation — e.g. empty street with no people — fails. CLIP has no reliable notion of “not”, so it returns the busiest scene instead. This is a known property of the model, not a bug in the app, but it will look like one. If a judge asks, say exactly that: “CLIP scores similarity, so negation is a known weak spot — we don’t claim it.”

7 · If they push on the numbers

  • Search accuracy: macro recall 84.6%, top-1 61.5%, zero false positives on hard negatives — measured on the 16 clips against ground truth checked frame by frame. Reproduce: python backend\scripts\search_accuracy_eval.py
  • Prediction: HR@10 0.79 (90% CI 0.76–0.83), PAI@10 2.37× against a 2.53× oracle ceiling — so we are at 94% of what any predictor could achieve on this data. We publish the ceiling on purpose, so the number is interpretable rather than inflated.
  • Surges: both planted surges are detected in the live top-10 during the weeks they run. The cyber-fraud ramp's second area, Satellite, sits exactly on the top-10 boundary and lands on either side of it between runs — the 180-day window slides with the seed time, so the weekend uplift shifts. We therefore quote the result per surge, which reproduces, not per area, which does not.
  • The data is synthetic and we say so on the slide. It demonstrates methodology, not real-world operational accuracy. Judges respect that far more than a number you cannot defend.

Everything runs on CPU, offline: CLIP ViT-B/32 + YOLOv8n + ArcFace + FAISS + SQLite. No GPU, no cloud, no API key. That is the deployability argument for an Indian police station.
